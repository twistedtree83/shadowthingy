# G1 — Scaffold: three-region layout and the debug panel

Issue: #2 · Branch: `sprint/gnomon-mvp` · Status: **shipped**

## What shipped

`gnomon.html` opens from `file://` and renders three regions — image canvas,
readout panel, result region — in instrument styling: monospace tabular
numerals, hairline rules, one accent (`--accent: #e0a44c`). The debug panel
toggles on **`** ` ** (backtick)** and renders both the debug registry and the
test registry with a pass/fail tally in its header.

No functionality beyond rendering, as specified.

## Decisions taken

- **The core publishes itself via `globalThis.Gnomon`.** That works identically
  in a browser and inside `node:vm`, so `test/_core.js` can extract the block
  and evaluate it with no shim. The purity gate forbids `window`; `globalThis`
  is the portable spelling.

- **The debug and test registries are factories, not singletons.** `Gnomon.debug`
  and `Gnomon.tests` are live instances the app writes to, but both expose
  `.fresh()` returning an independent one. Tests need isolated registries —
  without that, asserting "a failing check is reported as failing" would have to
  pollute the app's own suite list to do it.

- **Debug sections keep insertion order** (a `Map`, not an object). The panel
  should read top-to-bottom in pipeline order — vanishing points, then
  calibration, then sun — not alphabetically, which would interleave stages.

- **`t.close()` and `t.within()` carry their bounds into the detail string.** A
  failure in the panel then says *what* was violated without anyone opening the
  source. This matters because the panel is user-facing: the whole point of
  shipping the solar assertions visibly is that a sceptical user can check the
  engine rather than trust it.

- **A throwing suite is captured as a failed check, not propagated.** One broken
  suite must not blank the panel — the other suites' results are exactly what
  you need to localise the break.

## Snags

`assert.deepEqual` failed on values that were structurally identical. The core
runs in a separate `vm` realm, so `suite.checks.map(...)` returns an array
carrying *that realm's* `Array.prototype`, and strict `deepEqual` compares
prototypes by reference. Fixed with `Array.from(x, fn)`, which builds the array
in the calling realm.

**This will bite every later slice** that maps over a core-returned array in an
assertion. Use `Array.from`, or compare scalars.

## Left for later slices

- The readout rows are placeholders showing `—`. They have `data-read`
  attributes (`residual`, `tier`, `focal`, `elevation`, `azimuth`, `multiplier`,
  `dimensions`, `captured`, `objects`) so later slices can fill them by
  selector rather than restructuring the panel.
- `window.gnomonRenderDebug()` is exposed for slices that compute after load.
- The `.canvas-stage` div is where G5 mounts the image and G6 the marking layer.

## Note for whoever picks up G3

Write intermediates with `Gnomon.debug.set(section, key, value)` and call
`window.gnomonRenderDebug()`. Add assertions with `Gnomon.tests.suite(name, t =>
{...})` — they appear in the panel and are picked up by the headless suite
automatically, so add them once.
