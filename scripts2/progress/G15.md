# G15 — Report export: one self-contained file that outlives the session

Issue: #20 · Branch: `sprint/gnomon-mvp` · Status: **shipped**

## What shipped

`Gnomon.report.build()` — a pure function from the values the core produced to a
complete HTML document — plus the export button and download wiring. 14
headless assertions; 217 total.

## The gate, verified

A real export from the running app: **315 KB, zero external references, zero
`<script>` tags, two embedded images.** Opened in a browser context with
`offline: true`, it renders completely — both images decode, no request is
attempted, no errors.

Contents: the verdict, the marked image, the globe, the answer with its
tolerance, the calibration tier and every candidate, the recovered direction
vectors, the vanishing points with their condition numbers, the marks
themselves, what the image claimed about itself, the inverse solve, the fired
guards, and the stated assumptions.

## Decisions taken

- **The builder never touches the DOM, and there is a test that proves it.**
  It runs in the headless suite, where `document` is `undefined` — that it works
  at all *is* the assertion. A report and the screen it was taken from must not
  be able to disagree, and scraping rendered text is exactly how they would.

- **The tolerance travels with the answer, always.** Every band is printed as
  `p5 – p95` with the median in parentheses and de-emphasised. A reader handed
  only a median has been handed false precision, and the report is where that
  is most dangerous because the reader was not there when it was produced.

- **A withheld answer stays withheld in the report.** When a guard has refused,
  the headline says so where the answer would have gone. This is precisely where
  a suppressed number is most likely to be mistaken for a finding.

- **The residual is printed beside its noise floor**, because on its own the
  number means nothing — G9 and G14 established that its scale is entirely a
  property of the marking precision and scene geometry.

- **The report is light-themed while the app is dark.** It will be printed,
  emailed and read in daylight by somebody who is not using the tool. Matching
  the app's palette would have been consistent and wrong.

- **The blob URL is revoked on the next tick.** The click has already started
  the save, and holding it would keep the whole embedded image alive.

- **`npm run check:network` is run against the report itself** in the test
  suite, using the same `scan()` the gate uses on the app. The report has to
  meet the same standard as the thing that produced it.

## One bug

The camera model was escaped twice — once building the row and again in
`rows()` — so a model containing `<` would have rendered as a literal `&lt;`.
Harmless for safety (double-escaping is safe, just ugly) but wrong, and the
escaping test caught it by asserting the escaped form actually appears rather
than merely that the dangerous form does not.

## Observed while testing

The demo fixture's residual noise floor comes out around 25° once the reference
direction is being perturbed too — its poles are small and its reference is
short. That is why `weak-residual-check` fires, and it is correct. **G17 should
rebuild the fixture with larger objects and a longer reference**, which would
make it both a better demo and a scene where the residual guard can be exercised
for real.
