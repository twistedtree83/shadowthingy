# G9 — Monte Carlo uncertainty and the azimuth-only fallback

Issue: #10 · Branch: `sprint/gnomon-mvp` · Status: **shipped**

## What shipped

`Gnomon.montecarlo` — seeded generator, Gaussian point perturbation, focal and
principal-point sampling, circular statistics for azimuth, and a chunked job API
the shell drives through `requestIdleCallback`. 24 headless assertions; 158
total. 500 samples run in ~325 ms in the browser with the interface live.

## The finding that changed the design

**The focal-length sweep barely moves the elevation band.** Measured on a fixed
scene at σ = 0.5px:

| sweep | elevation band width |
|---|---|
| Tier 1, ±2% | 0.52° |
| Tier 4, ±15% | 0.55° |
| Tier 5, full range | 0.55° |

An eight-fold change in sweep moves the band by 0.03°. The reason is structural:
`d_up` and `d_sun` are both built with the *same* `f`, so scaling it rotates
both alike and their mutual angle is nearly preserved. **Elevation is genuinely
robust to focal length** — good news about the physics, but it means the
mechanism I had built for the honesty rule was in the wrong place.

My first monotonicity test passed on differences of 0.03° and gave false
comfort. That is the kind of test that makes a build feel verified while
verifying nothing.

**What a crop actually destroys is the principal point.** That translates every
vanishing point relative to `c`, which changes the recovered angles directly:

| principal point | elevation band width |
|---|---|
| known | 8.12° |
| unknown, σ = 5% of width | 9.17° |
| unknown, σ = 15% of width | 15.04° |
| unknown, σ = 25% of width | 21.97° |

So the Monte Carlo now samples the principal point, with σ = 0 when the centre
is trustworthy and 15% of the image width when `meta.cropped` is set. That is
the mechanism by which a cropped image earns its visibly wide band, and there
are tests asserting the crop's contribution exceeds the focal sweep's by more
than 5×.

A **stripped but uncropped** image legitimately gets a narrow elevation band,
because Tier 4 recovers `f` to better than 1% and elevation barely depends on it
anyway. That is honest rather than overconfident.

## The residual: base value, not the band

| scene | unperturbed residual | Monte Carlo band p50 |
|---|---|---|
| clean | 0.000° | 5.33° |
| pole leaning 12° | 1.142° | 5.02° |

The **unperturbed residual separates the two completely; the sampled band does
not** — it is dominated by marking noise and is, if anything, slightly *lower*
for the corrupted scene. **G14's guard must read the base residual.** Using the
band would give a detector that fires on clean scenes and stays quiet on broken
ones, which is precisely backwards.

The band is still worth reporting as a noise floor: it says how much residual
this scene's geometry produces from marking error alone.

## Other decisions

- **Circular statistics for azimuth.** A sun near due north straddles the 0/360
  seam, and naive percentiles put the median at 180° — pointing exactly the
  wrong way. Samples are unwrapped about the circular mean first, with a test on
  a sun at 1°.

- **Box-Muller discards its second variate** rather than caching it. Caching
  would make a draw depend on how many draws preceded it, which quietly breaks
  reproducibility when the sample count changes.

- **The previous band is dropped the moment marks change.** A band left standing
  while a new one computes belongs to marks that no longer exist, and would be
  read as current. This was a live bug found in the browser: loading a second
  image showed the first image's band.

- **An unbounded azimuth now explains itself.** A reference direction that
  recedes from the camera is foreshortened, so a few pixels of marking error
  swing its ground direction wildly. On the fixture, a 121px receding reference
  gives an unbounded azimuth where a 648px one crossing the view lands within a
  few degrees of truth. Without the explanation "unbounded" reads as a broken
  tool; with it, it reads as an instruction.

## The network gate cried wolf, and was fixed

It matched the bare word **"plausible"** and fired on a comment explaining the
network policy. A gate that cries wolf on prose is one people learn to ignore,
which is worse than not having one. Now: comments are blanked (preserving line
numbers), and the analytics patterns match product identifiers rather than
English words. The gate is also importable and has four tests of its own,
including one asserting a genuine violation is still caught on the correct line.
